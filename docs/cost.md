# コスト

状態: **費用要因の整理と、稼働時間の記録。金額は、請求への反映後に追記する**。

AWS 版では、概算を書いたあとに実績と突き合わせました。GCP 版は、単価を私が最新の公式価格で確認できていないため、**金額は書きません**。フェーズ 3（実機検証）で、請求の実績を記録します。見積もりが必要な場合は、[Google Cloud Pricing Calculator](https://cloud.google.com/products/calculator) で確認してください。

## 費用の要因

| 項目 | 課金のされ方（考え方） | dev | prod |
| --- | --- | --- | --- |
| Cloud SQL | インスタンスの稼働時間 + ディスク + バックアップ。**起動している間は、リクエストが無くても課金される。最大の固定費の見込み** | 共有コア・単一ゾーン | 専用コア・高可用（REGIONAL）。約 2 倍の費用要因 |
| Cloud Run | リクエスト処理中の CPU・メモリ。最小インスタンス 0 なら、リクエストが無い間はほぼ課金されない | 最小 0（scale-to-zero） | 最小 1（常時 1 台分が課金される） |
| VPC / private services access | 予約済みの内部アドレス範囲とピアリングそのものは、課金の対象としては小さい見込み（要確認） | あり | あり |
| Cloud NAT | 既定で作らない（`enable_nat = false`）。有効にすると、ゲートウェイの時間課金 + データ処理料がかかる | 無し | 無し |
| 外部 HTTPS LB | 転送ルールの時間課金 + データ処理料。**任意機能（既定は無効）** | 無効 | 任意 |
| Cloud Armor | ポリシー + ルール + リクエスト数。**任意機能（LB と一緒に有効化）** | 無効 | 任意 |
| Secret Manager | シークレットのバージョン数 + アクセス回数。少量 | あり | あり |
| Cloud Monitoring / Logging | ログの取り込み量が課金の対象（無料枠あり）。SLO・アラーム・ダッシュボードの扱いは、請求で確認 | 最小の想定 | 最小の想定 |
| state 用の GCS バケット | 保存量が極小のため、僅少 | あり | あり |

## 抑える工夫（実装済み）
- NAT を既定で作らない（AWS 版で、NAT がコスト最大の項目だった）。
- dev は scale-to-zero、共有コア、単一ゾーン、小さなディスク。
- LB / Cloud Armor は、フラグで無効にしておく。
- dev は、検証のときだけ起動し、検証後に `destroy` する。

## 注意すべき点
- **Cloud SQL は、停止しなくても、止めても、ディスクの課金が残る**ため、使わない期間は destroy が確実です。
- destroy のあとも、残るものがないかを、CLI で確認します（Cloud Run、Cloud SQL、VPC、private services access の割り当てアドレス、Secret Manager、Artifact Registry、ログ バケット、LB、静的 IP、サービスアカウント。AWS 版では、ログのグループが残りました）。
- 無料トライアルの残額と予算アラートを、検証の前後に確認します。
