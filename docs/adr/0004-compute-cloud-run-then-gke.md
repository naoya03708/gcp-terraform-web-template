# 0004. コンピュートは Cloud Run を先に、GKE Autopilot を後から追加する

状態: Accepted

## 背景
AWS 版の ECS Fargate に最も近いのは Cloud Run（サーバーレスのコンテナ実行）。一方、SRE の案件では Kubernetes（GKE）の経験を求められることも多い。両方を示したいが、作業量と検証の費用が増える。

## 決定
- **第1段階は Cloud Run** で全体（ネットワーク、DB、監視、CI/CD）を完成させる。
- **第2段階で GKE Autopilot** を、別モジュール（`modules/gke`）として追加する。ネットワーク・DB・監視は、第1段階と共有する。
- 基本設計は両方を見据えて書く。実装と実機検証は、段階ごとに行う。

## 理由
- 段階を分けると、費用と作業を段階的に抑えられ、第1段階だけでも公開できる品質になる。
- GKE を後から足す前提で、共有部分（VPC、DB、監視）を最初から分けて設計できる。

## トレードオフ
- 第2段階が完了するまでは、Kubernetes の実績としては示せない。
- SLI の元データが、Cloud Run と GKE（LB のメトリクス）で異なる。監視モジュールに、compute に応じた分岐を持たせる必要がある（ADR 0007）。
