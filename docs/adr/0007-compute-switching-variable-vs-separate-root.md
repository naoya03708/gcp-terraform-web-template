# 0007. コンピュートの切り替え方式（変数か、別ルートか）

状態: Proposed（第2段階の着手前に確定する）

## 背景
Cloud Run と GKE Autopilot を、同じテンプレートで提供する。切り替え方式が、コードの複雑さと、テストの量に影響する。

## 案
| 案 | 内容 | 長所 | 短所 |
| --- | --- | --- | --- |
| A | ルートに `compute = "cloudrun" \| "gke"` を持ち、モジュールを `count` で出し分ける | 1つのルートで完結し、共通部分（VPC・DB・監視）を再利用しやすい | 条件分岐が増え、テストの組み合わせが増える。監視のメトリクスの分岐も要る |
| B | 別ルート（`cloudrun/`、`gke/`）で、共通モジュールを呼ぶ | 各ルートが単純で、読みやすい | ルートが2つになり、`environments/` を作らない方針（ルート直下 + tfvars）と衝突しうる |
| C | 同時に両方を作れるようにし、フラグでそれぞれ有効化 | 比較検証がしやすい | 費用が増え、通常は片方で足りる |

## 仮の決定
第1段階では、Cloud Run のみを実装し、`compute` の変数は導入しない。第2段階の着手前に、案 A か C かを、実装して試した結果で確定する。案 B は、「ルート直下 + tfvars」の方針（ADR 0001）との整合のため、採用しない見込み。
