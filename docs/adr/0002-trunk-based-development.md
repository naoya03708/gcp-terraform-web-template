# 0002. トランクベース開発とタグによる prod 昇格

状態: Accepted

## 背景
環境ごとに長命ブランチを持つと、ブランチ間のずれ（ドリフト）と、マージの負担が増える。AWS 版では、トランクベースで運用した（AWS 版 ADR 0002）。

## 決定
- 長命ブランチは作らない。`main` が常にデプロイ可能な唯一の幹。作業は短命ブランチから、PR で squash マージする。
- 未完成の機能は、変数のフラグ（例: `enable_lb = false`）で無効のままマージする。
- 昇格は、ブランチではなく**タグ**で行う。main へのマージ → dev に自動 apply（変数 `AUTO_DEPLOY_DEV=true` の時のみ）、タグ `v*` → prod に、GitHub Environment の承認付きで apply。
- main の保護: PR 必須、必須チェック、linear history、force push 禁止、squash のみ、マージ後のブランチ自動削除。

## 理由
- 環境間の差を、コードではなく、変数と承認ゲートで表現できる。
- 誤って課金リソースを作らないよう、dev の自動 apply は明示的に有効化する。

## トレードオフ
- 小さな変更を頻繁にマージする規律が要る。
- 必須チェックが「最新の main への追従」を要求するため、複数の PR が並ぶと、更新の手間が出る（AWS 版で、Dependabot の PR で経験した）。
